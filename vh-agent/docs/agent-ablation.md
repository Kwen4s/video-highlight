# Agent 消融协议

## 要回答的问题

消融围绕用户最终拿到的候选进行，不比较 Agent 自评分：

1. 是否漏掉了人类愿意采用的看点；
2. 一条候选是否只包含一个可独立取舍的看点；
3. 候选是否容易直接采用或只需少量修改；
4. 字幕、本地位置模型、独立成片复核和全局选择各自解决了什么问题。

现有 10 条 AI 复核视频用于检查流程、召回和边界错误；加上 10 条银标后可做 20 条运行压力测试。正式产品数值等人类完成事件和编辑记录后再填写，不用旧预测、银标或模型自评代替。

## 固定主版本

主版本使用当前 v23：原生视频全片覆盖，可用时消费全文字幕和全部本地位置线索；每条事件对应一个可独立采用的核心看点；所有 supported 事件生成真实片段并由独立上下文复核；完整候选池最后统一选择并原子冻结。选择阶段从成片所见建立新会话工作段，早期解释和早期价值理由不进入选择视图，保留按需回查。每轮同步最新持久状态，选择前仍允许补看和修订，进入选择后不因临时待办退回扫描会话，核对结论持久保留；各段复核独立持久化。复核只提供事实与缺陷，主 Agent 统一生成采用价值和理由。边界是供人类继续调整的粗剪，独立复核只把缺少必要上下文、截断、混合多个独立看点和音画故障作为阻断缺陷。

单动作提交、视频观察登记锁、输入来源完整消费、事件版本、恢复和完整候选账本属于正确性约束。关闭它们会制造无效运行，不作为效果消融。

## 最小对照组

每个对照只改变一个机制，使用同一视频、用户目标、模型、采样、预算和评分代码：

| 变体 | 唯一变化 | 主要回答 |
| --- | --- | --- |
| Full v23 | 当前完整实现 | 产品基准 |
| 原选择上下文 | 保留扫描会话和早期价值理由 | 成片事实视图是否减少猜测和铺垫独立入选 |
| 复核预先评价价值 | 独立复核提供分数、理由和类型作为选择输入 | 重复评价是否造成事实偏移或错误去重 |
| 无单看点契约 | 移除事件单看点说明与 `mixed_focus` 复核 | 粒度约束是否降低人工拆分成本 |
| 无独立成片复核 | supported 片段直接进入候选池 | 复核是否减少事实不符、截断和混合看点 |
| 无全局选择 | 把全部复核通过候选交给编辑 | 最终选择是否降低删除和浏览成本，同时是否损伤召回 |
| 无本地位置线索 | 其余输入不变 | 本地模型带来多少新增召回及多少噪声 |
| 无字幕检索 | 其余输入不变 | 文字来源对台词事件和定位的贡献 |
| 仅原生视频 | 同时不提供字幕和本地线索 | 辅助召回能力的整体上限对照，不用于拆分单项贡献 |

只有数据中确实启用了某个输入来源时，才运行对应的去除实验。粗边界质量直接用人工修改量和编辑时间衡量，避免把调用次数当成剪辑质量。

视觉辅助实验另按问题设计：镜头边界只改变观察组织，embedding 只增加相关区间检索，局部密采样或 OCR 只增加细节核对能力。全片覆盖与最终选择保持相同。以转场、短动作、画面文字和跨镜头事件作为分组，比较事件召回、事实错误、重复观看区间、人工采用率及总耗时。当前默认链路未启用这些新增能力，因此不能把删除死代码算作它们的消融结果。

生产代码不加入长期实验开关。每个变体在独立提交或 worktree 中运行新的 `run_id`；评测产物的 `protocol.json` 和 `source/` 冻结实际源码、任务、输入及标注，使对照可复算和审计。

## 人工记录

标注以“可独立采用的看点”为单位。每个看点记录事件身份、决定性区间、可接受的完整边界，以及是否允许与另一看点合并。编辑实际操作另外记录：候选采用、排除、拆分、合并、修改后的起止时间和操作耗时。一个事件可以有多个可接受边界，但不能从待评预测反推答案。

每个候选最终归入一种结果：直接采用、改边界后采用、拆分后部分或全部采用、与其他候选合并后采用、排除。这样可以区分“事件找到了”和“交付形式好不好用”。

## 指标

主指标直接反映用户成本：

- **可用看点召回**：人类愿意采用的标注看点中，被任一候选覆盖的比例；
- **直接采用率**：不拆分、不合并、不改边界即可采用的候选比例；
- **最终采用率**：经过允许的人工编辑后仍被采用的候选比例；
- **人工拆分率**：需要拆分才能采用的候选比例，直接衡量事件过粗；
- **人工删除率**：候选中最终被排除的比例；
- **边界修改量**：采用候选的 `|最终起点-建议起点| + |最终终点-建议终点|`，同时报告中位数和 P90；
- **编辑耗时**：每条采用片段和每个视频的人工操作秒数；
- **每个采用看点的候选浏览量**：编辑为获得一个最终片段需要查看多少候选。

自动指标保留作定位：事件级 P/R/F1（IoU 0.3/0.5/0.7）、候选到复核再到选择的分阶段召回、决定性证据覆盖、重复预测、输出数量和时长、完成率、API/工具错误、模型调用数和墙钟时间。时间 IoU 和 Agent 分数不替代人工采用结论。

粒度另报告两个计数：**混合看点率**是输出候选中包含多个可独立采用看点的比例；**碎片化率**是同一标注看点被多个无法单独理解的候选拆散的比例。两者需一起看，避免通过无限切短片段降低混合看点率。

## 运行顺序

1. 当前 v23 已完成十视频实现对照：最终 10/10、必选覆盖 10/10，自动事件精度 62.5%、首轮完成 7/10；这不支持效果已经提高。详情见[稳定性复查](stability-review-20261001.md)。在 10 条 AI 复核短视频上运行当前 Full，确认 complete、状态约束和指标产物正常；再用 `--include-silver` 跑 20 条执行压力测试。两者都不写成人工效果结论。v17 的十视频结果和 v18 的定向修复验证见 [稳定性复查](stability-review-20261001.md)。
2. 人类数据就绪后先跑 Full、无单看点契约、无独立复核、无全局选择，回答候选质量和编辑成本的核心问题。
3. 对具有字幕和本地模型输入的视频再跑两个单项输入消融及仅原生视频对照。
4. 只在有可靠操作耗时记录的子集比较边界策略。

托管模型存在随机性。每个变体按视频配对运行相同次数，先保留逐视频原始结果；样本足够后报告均值和配对 bootstrap 置信区间。没有足够样本时只列原始计数，不宣称显著提升。
