# State v5 实现与验证（2026-09-29）

## 已实现

- 连续保存原生模型 Content 与工具交互、签名，按上下文预算开启新工作段；视频以哈希校验的文件引用持久化，发送时重建内联载荷。
- 字幕行稳定 ID、规范化查询、返回行集合和分页完成情况进入 checkpoint；已读正文可通过 read_state 取回。换工作段时恢复相关字幕及查询进度。
- 删除 event_store，采用 record_observation / update_event / read_state。新事件通过观察登记创建，多个发现原子保存并关联观察；update_event 只修改已有事件。
- 调用批次先落盘，每个工具的状态变化与结果一起提交；中断后继续未执行调用，复用已提交结果。独立成片复核单独保存进度。
- 按已知信息与业务变化检测停滞，保留跨恢复的计数；相同内容的等价分页查询和纯 reason 改写不会冒充进展。
- 时长不可行事件仍需修订或明确排除。完整池选择与冻结媒体协议不变。

现有 Pydantic、HTTPX 和原子写入足以完成此改造，没有新增包、兼容层或额外 Agent。AgentState 是持久业务状态的概念名称：实际业务读写仍集中在 VideoTools，state.py 提供检索与进展记忆，context.py 管理原生会话及预算。

## 本地验证

Agent 154 项测试通过；后端 23 项通过；Ruff 与 diff 检查通过。新增测试包含原生历史/签名保留、无 base64 检查点、分页读取与恢复、等价查询、批量事件关联、时长不可行的处置，以及工具执行前/提交后中断。

离线模拟 30 页、300 秒视频，多次上下文换段后全部页面记录保持完整并完成任务。此测试验证调度与状态保留，不替代真实长视频准确率评测。

## 首轮实测发现及修复

首轮 1/5 完成，另外 4 条分别因两次空响应、一次连接中断及一次上下文预算错误停止。成功的“十个亿”视频只查询两次字幕，读完全部 22 条；上一版同视频查询 9 次，其中 7 次无新增内容。最终仍只选出 0–21.52 秒回击片段，栽赃被模型判断为无需另剪。

预算错误来自换段时将未登记的旧视频全部重放，与新请求视频叠加超限。修正为新请求媒体优先，旧媒体按剩余预算装载，显式返回仍需重新读取的观察 ID；所有媒体引用与待办保留。新增相同 33 秒旧媒体加 17 秒新媒体的边界回归。

同时加入带类型的暂时性请求错误及有界同请求重试，记录每次尝试；新测试确认重试输入完全一致，工具不会重复执行。首轮失败保留在原目录，最终代码使用新的运行 ID，不迁移旧检查点或覆盖失败结果。

四份冻结媒体均通过 ffprobe 检查，含音轨、视频轨，媒体时长与公开边界一致（误差小于 0.1 秒）。运行目录中的 diagnose.py 可离线重算 diagnostics.json，不调用 API。

## 效果仍存在的问题

- 十亿视频的后段栽赃仍未入选。模型以“悬念结果未揭晓，不适合单独成段”登记 no_event_reason；状态记忆改进没有解决这条内容判断。
- 灰欲人生的搜身与称呼互动这次有独立事件记录及排除理由，没有把同一记录改写成另一件事；两段在当前复标中均为可选。
- 重生视频选出两段、覆盖 0–54 秒，接近整片。需要人工确认事件独立性与重复程度，并继续改进事件粒度和全局取舍；不能凭独立复核的高分认定这是优质高光。

当前评分器的推荐标签时间匹配结果：IoU≥0.3 时 P=0.75、R=0.75、F1=0.75；IoU≥0.5/0.7 时 P=0.5、R=0.5、F1=0.5。它尚未使用重生事件的 alternative_clips，且没有可选片段口径；标签也是 AI 开发复标。这些分数完整保留为诊断，不能宣布准确率提高。下一步应补齐评分口径，并在人工审定数据上检查事件拆分、重复选用与开放悬念的取舍。
