# 状态机与编辑协议验证（2026-09-30）

本文记录 v7/v8 的历史实测。后续产品决策确认结果交给人类编辑，v9 曾把 `boundary.trim` 改为非阻断建议；v10 已删除这个没有进入产品输出的复核字段，只保留实际成片缺陷检查。“一个候选只承载一个可独立采用的看点”和独立成片的 `mixed_focus` 检查继续保留。下列 v8 严格重做边界的结果仍作为历史证据保留，不代表当前策略。

运行目录：`outputs/evaluations/state_v7_20260930/`。使用 `reviewed-five-v2`、Gemini 3.7 Flash 和冻结的 `agent_quality.json`：单段 3–30 秒、不限输出数量与总时长、允许重叠。本地候选模型未配置；当前运行环境也没有声明可用字幕/ASR 工具。本轮因此验证原生音视频主链，检测输入不含标注答案。

## 状态机结论

- 五条视频的全部页面都在 `record_observation` 成功后才增加覆盖率。
- 视频送达后只开放绑定 observation ID 的登记动作；一次无效登记不会解锁扫描或借用媒体交付进展。
- 已完成页面不再被重复 `scan_video`。局部补看使用 `inspect_interval`。
- 每个最终候选都经过实际媒体独立复核，随后由 `read_state collection=candidates` 进入持久账本，再执行一次显式选择。
- 公开结果中的最终片段均为 `review_status=accepted`；partial 不发布待选片段。

因此 v6 的主要执行故障已经消除：第二条不再重复扫描后停滞，第三条不再因空响应永久失败，五条均能到达同一套确定性完成条件。

## 暴露的编辑问题

候选事件召回为 1.0，但复核后召回为 0.75。唯一损失来自“全家偷听我心声”：Agent 已发现妹妹内心承认栽赃的事件，却以“后续搜查结果未揭晓、不能独立看懂”为由在成片前排除。该理由把事件是否发生、剧情是否完结和最终观看价值混在了一起。

边界也偏宽。典型例子包括：

- 医院身份疑点的人工建议为 13.7–32.0 秒，输出为 4.0–33.83 秒；
- 称谓互动的可选建议为 40.0–45.5 秒，输出为 30.0–47.5 秒；
- 重生确认的短版建议为 41.5–52.0 秒，输出采用包含前世因果的 27.48–53.52 秒。后者能命中同事件的长版 alternative clip，但反映出模型倾向保留完整因果背景。

这些结果说明发现能力和运行稳定性已不再是当前首要瓶颈；剩余误差主要来自事件粒度与编辑节奏。

## v8 修正与定向复跑

当前实现进一步把事件核验和编辑取舍分开：

1. `rejected` 必须提交结构化 `rejection_category`。低价值、开放悬念和剧情继续不再是合法的提前排除理由；价值判断留到完整候选池选择。
2. `clip_infeasible` 只有在已经存在超时计划或阻断复核缺陷时才合法，不能用来包装普通偏好。
3. 独立复核新增 `boundary.keep/trim`。`trim` 会阻止冻结，要求主 Agent 修订必要证据和边界、重新生成媒体并再次复核。

30 秒上限定向复跑保留并输出了两个推荐事件：0.0–21.0 秒和 27.0–53.92 秒。第一个对人工边界 IoU 为 0.721；第二个不再丢失，但模型把“栽赃心声”和后续“掀被搜查悬念”视为一个事件，IoU 为 0.371。

使用产品默认 24 秒上限再次复跑时，第二事件首次 draft 明确返回时长不可行。Agent 随后补看 21–43 秒，修订事件为 30.0–53.92 秒，重新生成和复核后才冻结；最终两段均为 `accepted`。这证明时长上限不是静默截断，能够触发证据驱动的边界修订。模型仍选择保留搜查悬念，属于事件粒度判断，不应通过针对样例的固定秒数规则改写。

## 下一项效果工作

下一批人工标注应同时给出事件身份、决定性时刻、可接受替代边界和是否允许与相邻节拍合并。针对事件粒度做对照时，固定当前状态机、模型与输入能力，只比较“一个事件包含几个决定性变化”的契约；不要再改完成条件或加入具体剧情词规则。边界评价同时报告事件级 alternative IoU、核心证据覆盖和输出时长，避免把语义正确的长因果版本简单记成错误。
