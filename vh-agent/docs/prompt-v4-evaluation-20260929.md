# 提示与工具语言调整后的实测（2026-09-29）

五视频首次完成 3/5；两次 API RemoteProtocolError 中断后，从检查点继续，最终完成 5/5，输出 3 个片段。此次实测仍复现事件漏记和重复字幕检索，不能认为提示词调整已经解决 Agent 的主要问题。

## 改动与设置

统一位置线索、观察、事件、片段的含义，解释 supported/ready 与最终选择的区别；事件返回提供当前下一步操作。统一原片时间换算、证据引用、工具错误说明和复核缺陷描述。修改剪辑明确要求先更新事件，再生成片段。

Gemini 模型配置为 gemini-3.7-flash，视频采样 4 FPS，片段范围 3–30 秒，不限数量和总时长，允许重叠。启用字幕检索，未启用本地候选模型。实际请求通过项目配置的 API 服务发送。

运行目录：`outputs/evaluations/prompt_v4_20260929/`。protocol.json 保存完整标注、输入哈希、任务、配置和源码快照；首次成绩单独保存在 metrics.first_attempt.json / report.first_attempt.md。恢复没有重跑已完成视频。

## 下一步的具体修复点

1. 观察结论与事件登记分开，仍能造成“描述发现、没有进入事件池”。需要改记录契约与事件处置流程，不能只增加“不要遗漏”的提示。
2. 已读字幕没有进入持久工作上下文，模型重复请求全文。需要保存检索覆盖和已读内容身份，用实际新增信息判断进展。
3. 独立复核能拦截不合格成片，但仍出现“完整闭环”式取舍。应通过人工审定的可选片段验证标准，不能把全部低强度冲突强制选入。

## 实测后补充的错误格式修正

首次实测还暴露了 Pydantic 原始校验信息泄漏到工具返回的问题。后续改为 fields 数组，只含字段路径、错误类型和简短原因，去掉输入对象回显及文档链接；无效 page_id 提示从当前 progress.next_page 或 pages 取得。新增缺字段测试，Agent 全套 138 项测试通过，Ruff 通过。

五视频主结果对应补充修正前的冻结源码。补充修正后的第二视频复跑单独保存到 `outputs/evaluations/prompt_v4_errors_recheck_20260929/`，不覆盖或混入主结果。

补充复跑结果：34.8 秒、10 次模型调用后以 `repeated_action_without_progress` 停止，状态 partial。首次 scan_video 返回页面拆分，随后模型连续检索字幕，没有完成视频观察。9 次字幕检索中，前两次已读完全部 22 条，后 7 次无新增内容。未发生参数校验错误，因此自然运行没有触发新的字段错误格式；该格式由回归测试验证。本轮没有将停止后的恢复成功充作一次成功复跑，失败轨迹完整保留。

因此，当前最终代码通过 138 项测试，但单视频复跑仍可陷入检索循环。主轮恢复后的 5/5 完成不能代表运行稳定；提示语言整理已完成这一轮验证，下一步优先修复检索记忆和无进展判断。
