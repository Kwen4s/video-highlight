## v10 历史稳定性结论

v10 在当时这批短视频上的**事件发现和主要输出较稳定**，但运行耗时、工具参数重试和粗边界仍不稳定。两次相同协议对 5 条盲标视频的完成结果均为 5/5，必选事件均为 6/6；最终输出在 IoU≥0.5 时的一致性 F1 为 0.952，匹配片段平均边界 IoU 为 0.946。一次复跑多保留了《绝代枭雄》的可选悬念片段，因此不能把固定 seed 当作确定性保证。

准确率结论仍受标注限制。当前 10 条 labeled 数据全部未经过人类确认，其中前 5 条复标时看过旧预测，后 5 条虽为盲标，但必选事件只有 6 个。盲标组 6/6 的召回率 95% Wilson 区间仍为 0.610–1.000，不能据此声称模型已经达到稳定的真实召回率。

## 运行问题

完整 10 条运行共发起 198 次模型调用，总耗时 3135.2 秒；单视频耗时中位数 317.1 秒，P90 为 487.1 秒。模型请求耗时中位数 10.4 秒，P90 为 26.6 秒。一次请求在 300 秒处发生 `ReadTimeout`，有界重试后完成；该次成功请求总耗时为 321.0 秒。当前瓶颈主要是模型往返和上游长尾，不是本地视频预处理。

完整运行有 16 次无效工具调用，其中 9 次来自事件版本语义歧义：工具输入中的 `version` 容易被模型理解为写入后的新版本，而状态机把它当作乐观并发令牌。现已把工具输入改成 `expected_version`，并明确要求原样使用状态返回的 `event.version`；内部版本只出现在状态输出中。修改后的《帝后也疯狂》定向复跑没有版本冲突，核心片段从先前的 32–60 秒收紧为 37–50 秒，和 38–50 秒标注的 IoU 为 0.923。该轮仍有 3 次其他无效调用，分别是提交不完整事件、把旧观察混入本次登记，以及证据区间超出观察范围；单条结果不足以证明整体调用数下降。

## 本轮修正

- Gemini 请求增加可配置的 `VH_GENERATION_SEED`，评测默认使用 7。Gemini 的 seed 只提供尽力复现，稳定性仍由重复运行验证。参见 [Gemini generateContent API](https://ai.google.dev/api/generate-content) 与 [Vertex AI 生成参数说明](https://cloud.google.com/vertex-ai/generative-ai/docs/multimodal/content-generation-parameters)。
- 新增 `vh evaluate compare`，要求 Agent 代码和设置相同，并验证共有样本的视频、任务和冻结标注一致；结果持久化到 `outputs/evaluations/comparisons/`。
- 评分器分开报告事件发现、原始边界 IoU、标注来源 cohort、95% Wilson 区间、模型调用、请求耗时、请求错误和无效工具调用。
- 数据集加载会拒绝重复 ID、缺失 manifest、越界区间和重复事件 ID；10 条 labeled 与包含 silver 的 20 条数据均通过校验。
- supported 事件返回确定性的 `draft_preview`，在真正渲染前显示建议边界、时长和不可成片原因，减少边界问题到后期才暴露。
- 事件写入输入与持久状态分离：输入使用 `expected_version`，状态输出保留服务器生成的 `version`。

### 与视频 Agent 设计的关系

代表性产品与论文仍使用视觉特征、embedding 检索和局部观察。我们保留“全片覆盖、事件记忆、定向补看、成片复核、完整池选择”主线；删除无人消费的分数不等于证明视觉辅助无用。对照来源及机制见 [架构对照](react-video-agent-design.md#与代表性视频-agent-的对照2026-10-01)，单项验证口径见 [消融协议](agent-ablation.md)。

镜头信息适合组织观察，embedding 适合查找相关区间，高帧率与 OCR 适合确认短动作或画面文字。先检验它们是否减少漏检与重复观看，再接入实际工具；不恢复旧的高光分数混加与候选前截断。

下一步速度瓶颈是媒体重复传输、保守预算导致的拆页和上游响应长尾。Gemini 官方推荐重复请求使用文件引用，但当前配置网关的 `GET /v1beta/files?pageSize=1` 实测返回 HTTP 404，尚未证明它支持 File API。当前不切换端点或伪造文件引用。长视频还需单独验证；现有短视频的耗时不能外推为 26 分钟素材的服务水平。


## v21：依据成片事实覆盖可用看点

这次改动处理选择依据和输出一致性：候选直接使用独立成片复核的 `visible_event`、`highlight_type`、分数及评价；初看描述与早期价值理由都移出选择视图，完整记录保留在状态中供按需回查。删除 `EventContent.highlight_type`，公开描述和类型均来自同一次成片复核。选择阶段比较独立吸引力及相对其他候选的新增价值，铺垫或重复关联写入取舍理由，不设置固定分数门槛。

进入选择时从最新持久事实建立新会话工作段，不继续传入扫描历史、完整工作事件和旧工具回显。完整候选池保留，所有候选都需要明确取舍。补看、修订、完整事件回查和已启用的字幕检索仍可使用；阶段与待请求一同持久化，恢复未完成选择请求会重发相同输入。没有增加裁判或固定模型调用。

本地验证：172 项有效测试通过，Ruff 与 diff 空白检查通过。回归覆盖早期猜测不成为公开事实或类型、早期价值理由不进入选择视图、20 条完整候选不提前截断、分析阶段原生签名和媒体引用保留、选择阶段新工作段、中断后原请求恢复以及修订后重新复核。删除了一条重复的工具集合断言测试。

评测入口新增 `vh evaluate compare --kind revision`，允许源码不同，但配置、共有视频哈希、任务及标注仍须相同。对照保存每轮源码指纹，并报告共有样本的事件精度、召回和输出一致性；默认 `--kind repeat` 仍用于相同实现的重复运行。

## v23：事实、取舍和恢复

独立复核只描述实际成片、生成分类并报告具体剪辑缺陷，删除复核的分数和价值理由。选择状态只提供事件 ID、版本、边界和 `visible_event`；初看解释、成片分类和旧价值评价不提前影响比较。主 Agent 对完整候选池一次生成 `score`、取舍理由和保留决定，公开分数与理由来自同一决定。所有候选都需明确处理，预算仍只在最终选择执行。

第一次进入选择时重建会话；之后补看、登记与修订保持该工作段。临时待办不使系统退回扫描会话，刚看过的视频和判断不会在再次选择前被清掉。最近补看结论进入 `inspection_memory`，待修事件当前版本和最新缺陷进入 `repair_events`，更早记录按需回查。两条针对补看后恢复、修订后新增缺陷的测试先复现会话丢失，再验证修复。

### 网关错误修复和失败证据

当前代码用 HTTP 5xx 类别处理服务器错误，替代漏掉代理状态码的枚举；认证与无效请求仍直接失败。重试保持相同请求、端点和模型，沿用三次上限。Cloudflare 将 524 定义为上游超时：[官方说明](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/)。

修补后的独立定向运行 `react_v23_gateway_retry_20261001` 1/1 complete，明确重生事件 1/1 覆盖，输出 2 条，用时 332.2 秒。实际再次遇到 HTTP 524，trace 标为 `retryable: true`，第二次请求成功。此运行是[当前处理逻辑定向验证](../outputs/evaluations/react_v23_gateway_retry_20261001/report.md)，不替换原十视频的 partial 记录。另一个开篇离婚对峙未匹配标注，自动事件精度 50%，不写作准确率提升。

源码冻结后仅增加 HTTP 错误分类、无工具调用时的失败文本记录和评测停止原因/累计计时，未再次改动剪辑决策。当前失败文本会写入 trace，已知 API 密钥从公开文本中移除，原生会话签名保持原样；每次尝试的 `stop_reason` 保存在 `execution.json`。原冻结版本没有独立保存策略拒绝文本，恢复轮换后无法从其 trace 还原全文，现场读取说明保留为诊断记录，不伪造原始日志。

### 仍需解决的效果问题

v23《京婚》0–15.52 秒采用理由描述逗笑与接孩子，没有再写“假扮恩爱”；但独立复核分类仍含“假扮夫妻”。片内直接可见的是提醒表现恩爱、牵手和逗笑，关系推断尚无直接确认。移出选择输入减少了分类对取舍的影响，没有消除复核模型本身的推断风险。
