# 剧情语境下的高光选择与定位

更新：2026-10-18。两阶段数据已生成，独立训练环境见下文；训练加载器、模型训练与 Agent 接入尚未实现。

## 模型承担什么

本地模型结合画面与对白，提供精彩核心区间。Agent 根据这些位置重点查看、确认看点、补上下文并剪辑。当前 Agent 仍连续查看全片；减少重复观看由后续调度接入完成。

短剧的铺垫与精彩常共享人物、场景和情绪，差别可能只是一句揭晓或一次反击。本方法保留共同语境，利用标注过程中真实发生过的取舍变化优先选择易混淆窗口，再通过集合级奖励学习选什么、选几个、圈在哪里。

采用 **Qwen3.5-9B + LoRA**，冻结视觉编码器与连接模块，训练语言部分。推理只加载一个模型，输出时间区间，不增加分类头、理由或自报分数。基座位于 `/data0/wkw/video-highlight/models/Qwen3.5-9B`。

## 输入与输出

每次负责 20 秒，前后各看 15 秒，并提供观看范围内及此前最多 90 秒的对白。视频从 2 FPS 开始，训练与推理共用输入构建器。20 秒是负责范围，高光通常几秒，优先 15 秒以内。

观看范围使用原片秒数，模型输入时间与答案使用窗口相对秒数。核心中点决定窗口归属，跨边界核心保留完整起止。模型关闭显式思考输出，只返回：

```json
{"segments":[{"start_sec":18.2,"end_sec":23.6}]}
```

没有高光返回空列表。映射回原片时加观看起点，合并窗口结果时去重。

任务提示词：

> 结合画面和对白，找出值得单独回看的精彩核心，圈住精彩实际发生的台词、动作或反应。普通铺垫和重复内容留作理解前情。片段通常几秒，优先 15 秒以内。只报告核心中点位于本次检测范围的片段，并保留完整起止。没有高光时返回空列表。时间使用当前视频窗口的秒数，按时间顺序返回指定 JSON。

检测范围由程序提供。初始视觉预算 8,192 token，总序列预算 16,384 token；实际解码需统计帧数与 token，控制空间尺寸，超预算样本明确重新分窗。不能静默截去尾部或答案。现有标签主要由 1 FPS 画面和对白产生，小数时间不代表逐帧精度。

## 唯一数据划分

入口：`/data0/wkw/video-highlight/datasets/vl-001/`。字段、命令和来源以 [vh-data README](../vh-data/README.md) 为准。

| 文件 | 窗口数 | 用途 |
| --- | ---: | --- |
| `sft/train.jsonl` | 4,778 | 全部完整监督训练窗口 |
| `gspo/train.jsonl` | 908 | 集合选择继续优化 |
| `val.jsonl` | 550 | 选参数和权重 |
| `test.jsonl` | 446 | 固定测试 |

训练／验证／测试按整剧隔离，分别为 44／5／4 部剧。只有负责范围被明确正负标签完整覆盖、核心完整可见的窗口进入训练，未知区域不变成空答案。

GSPO 包含全部 454 个历史易误选位置关联窗口及 454 个补充窗口，按 SFT 的空／单／多高光比例分层，在类别内按剧轮流抽样，种子 42。908 条均属于 SFT，是同一任务的继续优化；验证和测试独立。历史判断只影响采样，当前有效答案保持原样。

输入只使用视频、范围和对白。SFT 将区间作为 assistant 目标；GSPO 将参考区间单独交给奖励函数，提示中不含答案。`source/` 的全部 952 条整视频标签和对白用于整集评估，避免只评价已筛选窗口。

## 两阶段训练

先做短程 LoRA SFT，学习任务标准、空答案及时间格式，仅监督答案 token。起始配置为 rank 32、alpha 64、dropout 0.05、学习率 5e-5、有效 batch 16，先跑一轮。Qwen3.5 的混合注意力结构需按实际模块检查 LoRA 注入范围并记录可训练参数。

再用 GSPO 对同一输入采样 4 份区间列表，以完整回答的相对奖励更新策略，起始学习率 1e-6。复用成熟框架的序列级重要性权重与裁剪，不另加辅助损失。

唯一任务奖励是区间集合的软 F1。预测集合 P 与参考集合 G 进行最大权重一对一匹配 M，权重为时间 IoU：

```text
R(P,G) = 2 × Σ[(p,g) ∈ M] tIoU(p,g) / (|P| + |G|)
```

双方都空奖励为 1，仅一方为空为 0。无效 JSON、非有限数值、反向或越界区间奖励为 0。重复预测和漏选通过一对一匹配及分母受到惩罚。未知区域不参与任务奖励；训练窗口已通过完整监督筛选。

固定种子 42。组内奖励全部相同时记录其比例；以验证集的召回、误选和有效奖励组比例决定训练轮数。数据能否支持收益由训练结果判断，目前没有性能结论。

## 实施与评估

1. 用实际 GPU 完成单批视频解码、LoRA 前后向，记录显存、RAM、token 和速度，确认训练框架支持当前模型。
2. 实现共用输入构建器，核对视频时间与输出还原，启动 SFT。
3. 用 SFT 权重启动 GSPO，验证集选权重；完成后对固定测试剧做整集推理。
4. 以区间列表接入 Agent 候选工具，再测端到端完成时间与编辑可用性。

检测评估报告事件召回、误选、匹配 tIoU、空窗口误报、每分钟候选数量与推理耗时。整集评估覆盖全部目标视频，对未知区域预测单独统计。训练权重与日志写 `runs/`，解码缓存写 `cache/`，均位于 `/data0/wkw/video-highlight/`。
